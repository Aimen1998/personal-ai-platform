# ADR-002: Licensing Audit

**التاريخ:** 2026-09-04

**الحالة:** مقبول

## السياق

المشروع يعتمد جزئيًا على مشاريع مفتوحة المصدر، وقد يتم دمج بعض مكوناتها أو استخدامها كاعتماديات في المراحل القادمة.

نحتاج إلى التأكد من أن تراخيص المكونات المستخدمة لا تفرض قيودًا تتعارض مع هدف المشروع أو مع نشر `personal-ai-platform` تحت MIT.

لذلك سيتم التعامل مع الترخيص كقرار هندسي، وليس كأمر ثانوي بعد اختيار التقنية.

## القرار

قبل دمج أي مشروع أو مكون رئيسي في المنصة، يجب:

1. تحديد الترخيص الفعلي للإصدار المحدد المستخدم.
2. مراجعة شروط الترخيص ومقارنتها بطريقة استخدامنا للمكون.
3. توثيق أي مكون ذي ترخيص غير متوافق أو غير واضح قبل اعتماده.
4. عدم افتراض أن وصف المشروع بأنه "Open Source" يعني تلقائيًا أن استخدامه متوافق مع ترخيص مشروعنا.
5. تفضيل المكونات ذات التراخيص المتوافقة بوضوح مع أهداف المشروع.

سيتم إجراء تدقيق ترخيص فعلي للمكونات الرئيسية قبل اعتمادها في الإنتاج.

## البدائل المرفوضة

### الاعتماد على وصف GitHub للمشروع فقط

مرفوض لأن وصف المشروع أو كلمة Open Source لا تكفي لتحديد الحقوق والقيود القانونية الفعلية.

### نسخ أو دمج مكون قبل مراجعة ترخيصه

مرفوض لأن تغيير الترخيص أو شروط الاستخدام قد يؤثر على إمكانية توزيع المنصة.

## النتائج

### الإيجابيات

* تقليل مخاطر الترخيص مستقبلًا.
* معرفة واضحة بما يمكن دمجه في المشروع.
* الحفاظ على إمكانية توزيع `personal-ai-platform` تحت MIT.
* سهولة إجراء مراجعة قانونية وتقنية لاحقًا.

### السلبيات

* إضافة وقت بسيط لكل dependency جديدة.
* قد نضطر إلى استبدال بعض المكونات بعد التدقيق.

## حدود هذا القرار

هذا ADR يحدد سياسة التعامل مع تراخيص المكونات.

لا يقرر الترخيص النهائي لكل dependency مستقبلية دون مراجعة الإصدار المحدد منها.

أي مكون جديد ذو ترخيص غير واضح أو مقيد بشكل كبير يحتاج إلى مراجعة منفصلة قبل اعتماده.
