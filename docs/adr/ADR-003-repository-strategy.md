# ADR-003: Repository Strategy

**التاريخ:** 2026-09-04

**الحالة:** مقبول

## السياق

المشروع يحتوي على جزأين مختلفين في طبيعة الملكية والنشر:

* `personal-ai-platform`: المشروع العام الذي يحتوي على المعمارية والوثائق والمكونات القابلة للنشر.
* `personal-ai-core`: Core خاص بالمشروع وقد يحتوي لاحقًا على منطق داخلي وبيانات أو إعدادات لا نريد نشرها.

نحتاج إلى فصل واضح بين ما يمكن نشره وما يجب أن يبقى خاصًا.

## القرار

سيتم استخدام مستودعين منفصلين:

### Public Repository

`personal-ai-platform`

* Public
* MIT
* يحتوي على الوثائق والمعمارية والمكونات العامة.
* لا يحتوي على أسرار أو بيانات تشغيلية خاصة.

### Private Repository

`personal-ai-core`

* Private
* لا يتم وضع License مفتوح المصدر عليه في هذه المرحلة.
* يحتوي على منطق Core الخاص بالمشروع.

الفصل بين المستودعين هو فصل للملكية والنشر، وليس بالضرورة فصلًا نهائيًا لكل مكون تقني.

## البدائل المرفوضة

### مستودع واحد لكل المشروع

مرفوض لأنه يجعل الفصل بين الكود العام والمنطق الخاص أكثر صعوبة، ويرفع خطر نشر مكونات خاصة بالخطأ.

### جعل Core عامًا منذ البداية

مرفوض لأن Core قد يحتوي لاحقًا على منطق أو مكونات لا نريد نشرها.

### استخدام ترخيص Open Source مقيد كحل وسط

مرفوض كخيار افتراضي للمكونات التي نريد اعتبارها جزءًا من المشروع العام؛ يجب تقييم كل ترخيص بشكل مستقل.

## النتائج

### الإيجابيات

* فصل واضح بين المشروع العام والمنطق الخاص.
* تقليل خطر تسريب الكود أو البيانات الخاصة.
* إمكانية تطوير المشروع العام بشكل مستقل.
* وضوح أفضل عند التعاون أو نشر أجزاء من المشروع.

### السلبيات

* إدارة مستودعين بدل مستودع واحد.
* الحاجة إلى تعريف حدود واضحة بين `platform` و`core`.
* قد نحتاج لاحقًا إلى إعادة تقييم الحدود إذا تغيرت المعمارية.

## حدود هذا القرار

هذا القرار يحدد استراتيجية المستودعات في المرحلة الحالية.

لا يحدد كيفية تقسيم كل ملف أو خدمة بين المستودعين.

أي تغيير جوهري في حدود `platform` و`core` يجب أن يكون موثقًا بقرار معماري جديد.
